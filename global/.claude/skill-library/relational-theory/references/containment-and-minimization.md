# Conjunctive queries: containment, equivalence, minimization, evaluation

Read this when you need a decision procedure: "is plan A equivalent to plan
B", "is this join redundant", "can this query be answered from that
materialized view", "is this predicate implied", or when choosing an
evaluation strategy for multi-way joins (acyclic vs cyclic). This is the one
area of query theory where equivalence is decidable, and an optimizer can
afford to run the algorithms because queries are small.

---

## 1. Conjunctive queries (CQ)

A CQ is a range-restricted FO formula built from relational atoms, `∧`, and
`∃`: `{ ⟨ē⟩ | ∃ȳ R1(z̄1) ∧ … ∧ Rn(z̄n) }`, written in rule form
`Q(ē) :- R1(z̄1), …, Rn(z̄n)`. Range restriction (every head variable occurs
in the body) is exactly what makes a CQ domain independent.

- `CQ` ≡ SPC algebra ≡ SQL `SELECT … FROM … WHERE` with conjunctions of
  equalities (column = column, column = constant). Effective translations in
  both directions.
- `CQ=` (equalities in the body) defines the same queries as `CQ` for
  satisfiable queries; a `CQ=` is unsatisfiable iff its equalities force two
  distinct constants equal — decidable by union-find. Every satisfiable `CQ=`
  compiles to a `CQ` by substitution.
- `UCQ` ≡ positive RA ≡ nonrecursive Datalog with one output predicate.
- `CQ≠`, `CQ<` (CQAC: CQ with arithmetic comparisons), `CQ¬` (negated atoms)
  are the important extensions; each changes the complexity class of
  containment.

**Canonical (frozen) database** `D_Q`: replace each variable by a distinct
fresh constant; the body atoms become the facts. A CQ is a homomorphism
pattern: `t ∈ Q(I)` iff there is a homomorphism (constant-preserving map)
from the body of `Q` into `I` that sends the head to `t`.

---

## 2. The homomorphism theorem (Chandra & Merlin, STOC 1977)

> For CQs `Q1, Q2` with the same head arity, `Q1 ⊑ Q2` (set semantics,
> all databases) **iff** there is a homomorphism `h : vars(Q2) → terms(Q1)`
> that maps every body atom of `Q2` to a body atom of `Q1`, maps the head of
> `Q2` onto the head of `Q1`, and is the identity on constants.
> Equivalently: the frozen head of `Q1` is in `Q2(D_{Q1})`.

Proof idea: (⇐) compose `h` with any satisfying valuation of `Q1`;
(⇒) evaluate `Q2` on `D_{Q1}` — the identity valuation of `Q1` produces the
frozen head, so `Q2` must produce it too, and its satisfying valuation is
`h`.

Worked example over an edge relation `a`:

```
p(X,Z)   :- a(X,Y), a(Y,Z)                 -- paths of length 2
r(W,W)   :- a(W,U), a(U,W)                 -- 2-cycles
t(L,N)   :- a(L,M), a(M,N), a(M,S)         -- path of length 2 + extra out-edge of M
```

- `r ⊑ p`: `X↦W, Y↦U, Z↦W` maps `p`'s body into `r`'s and head to head.
- `p ⋢ r`: `r`'s head repeats a variable; `p`'s head `(X,Z)` cannot be
  matched by any map sending both head positions of `r` to one variable.
- `p ≡ t`: `t → p` via `L↦X, M↦Y, N↦Z, S↦Z`; `p → t` via the identity on
  `X,Y,Z`. So `t`'s third atom is redundant — one fewer join.

**Complexity.** Containment and equivalence of CQs are NP-complete (combined
complexity: both queries are input). NP-hardness comes from repeated
predicates; if no predicate occurs more than twice in the *contained* query
`Q1` (the homomorphism target) the test reduces to 2-SAT and is linear
(Saraiya 1991). If `Q2` has bounded treewidth (or bounded hypertree
width) the homomorphism test is polynomial (Chekuri & Rajaraman, ICDT 1997).
The problem is literally constraint satisfaction: `Q1 ⊑ Q2` iff the CSP
"`D_{Q2}` → `D_{Q1}`" is solvable (Kolaitis & Vardi, JCSS 2000), so CSP
techniques (arc consistency, backtracking with ordering heuristics) are the
practical implementation.

## 3. Minimization (the core)

A CQ is minimal if no body atom can be removed while preserving equivalence.
The minimal equivalent CQ is the **core** of `D_Q` (with head variables
treated as constants); it is unique up to variable renaming and is
obtained by deleting atoms only (never needs new atoms).

```
minimize(Q):
  for each atom α in body(Q):            # any order; result unique up to iso
     Q' := Q with α removed
     if Q' is safe and exists hom h: Q -> Q' fixing the head:
         Q := Q'                          # Q ⊑ Q' is automatic (fewer atoms); h gives Q' ⊑ Q
  return Q
```

`|body|` homomorphism tests, each NP in the worst case; for typical SQL
blocks (≤ 20 atoms, few self-joins) it is cheap. Relevance to the engine:

- It removes redundant self-joins generated by view expansion, ORMs, and
  security-predicate injection.
- It is **set semantics only**. Under bag semantics, removing an atom always
  changes multiplicities unless it is an *exact duplicate* and the base
  relation is a set (bag-set semantics). Use it only in a
  duplicate-insensitive context (`DISTINCT`, `EXISTS`, semijoin side,
  `MIN/MAX`) or after proving the removed atom matches exactly one tuple
  per binding — which is a *key*-based argument (see
  `dependencies-chase-and-semantic-optimization.md`).
- Minimization under constraints = chase, then minimize (the chase may add
  atoms that make others redundant), then drop atoms implied by constraints
  ("backchase").

## 4. Beyond plain CQs

### 4.1 Unions (UCQ)

Sagiv & Yannakakis (JACM 1980): for UCQs without built-ins,
`Q1 ∪ … ∪ Qm ⊑ P1 ∪ … ∪ Pk` iff every `Qi` is contained in some single `Pj`.
So UCQ containment is NP-complete, and UCQ minimization = minimize each CQ,
then drop any disjunct contained in another. This "each disjunct in one
disjunct" property **fails** once comparisons or negation are allowed.

### 4.2 Comparisons (CQAC)

With `<, ≤, ≠` over a dense total order, one homomorphism is no longer
enough; containment needs reasoning by cases over all linear orderings of the
variables (Klug, JACM 1988). Example:

```
Q1() :- R(x,y), R(y,x)
Q2() :- R(u,v), u ≤ v
```

`Q1 ⊑ Q2` holds (one of `x ≤ y`, `y ≤ x` is true), yet neither mapping
`u↦x,v↦y` nor `u↦y,v↦x` is justified by `Q1`'s own constraints alone.
Test: for every **basic canonical database** — a partition of `Q1`'s
variables into ordered blocks consistent with `Q1`'s comparisons — the frozen
head must be in `Q2`'s answer. Equivalently: `Q1`'s comparisons logically
imply the disjunction, over all body homomorphisms `h`, of `h(Q2`'s
comparisons`)`.

- CQAC containment is Π2p-complete (already with only `≠`).
- Containment of CQs with negated atoms is Π2p-complete.
- Restricted shapes (e.g. only left-semi-interval comparisons
  `x < c`, `x ≤ c` in the containing query) are in NP and admit the
  single-homomorphism test (Afrati, Li, Mitra, TCS 2006, survey).

Engine relevance: **predicate implication** for range predicates (index
matching, partition pruning, MV matching) is a fragment of this. Keep the
implemented fragment conjunctive with single-variable bounds and
column=column equalities, where implication is polynomial (interval
arithmetic over equivalence classes); fall back to "not implied" outside it.
Unsound "implied" answers produce wrong results; incomplete "not implied"
answers only lose an optimization.

### 4.3 Datalog

- Datalog ⊑ Datalog: undecidable (Shmueli 1987).
- CQ (or UCQ) ⊑ Datalog: decidable — freeze the CQ, run the Datalog program
  to fixpoint on `D_Q`, check for the frozen head. EXPTIME-complete in
  combined complexity (Datalog evaluation), polynomial for a fixed program.
- Datalog ⊑ UCQ: decidable (doubly exponential; Chaudhuri & Vardi).
- Boundedness ("is this recursion equivalent to some finite unfolding?") is
  undecidable (Gaifman, Mairson, Sagiv, Vardi, LICS 1987), so an optimizer
  cannot in general replace a recursive CTE by a fixed number of joins.

## 5. Bag and bag-set containment

Notation: `⊑b` bag containment (multiplicity-wise ≤), `≡b` bag equivalence,
`≡bs` bag-set equivalence.

| Problem | Result | Source |
|---|---|---|
| `≡b` for CQs | iff isomorphic (graph-isomorphism-hard, in NP) | Chaudhuri & Vardi, PODS 1993 |
| `≡b` for UCQs | iff isomorphic as multisets of CQs | Cohen, Nutt, Serebrenik, PODS 1999 |
| `≡bs` for CQs | iff isomorphic after removing duplicate atoms (Lovász's homomorphism-counting theorem underneath) | Chaudhuri & Vardi |
| `≡b`, `≡bs` for UCQ≠ | in PSPACE | Cohen et al.; Nutt et al. |
| `⊑b` for CQs | Π2p-hard; decidability open (as of the entry) | Chaudhuri & Vardi |
| `⊑b` for UCQs | undecidable (reduction from Hilbert's 10th problem) | Ioannidis & Ramakrishnan, TODS 1995 |
| `⊑b`, `⊑bs` for CQ≠ | undecidable | Jayram, Kolaitis, Vee, PODS 2006 |
| Set containment of CQs | NP-complete | Chandra & Merlin |

Transfer lemma (Green, ICDT 2009): bag semantics reduces to bag-set
semantics by encoding multiplicities, so bag-set containment of UCQs is
also undecidable.

Takeaways an optimizer can act on:

1. Under bags, **equivalence is easier and rarer** than under sets: the only
   equivalence-preserving transformations of a CQ body are variable
   renamings. Every "redundant join removal" in a bag context is really a
   *constraint-based* argument (key/FK), not a containment argument.
2. Under bag-set (base tables have keys), exact duplicate atoms can be
   removed; nothing else.
3. **Bag containment is not a safe tool** for MV matching or subsumption
   tests. Use set containment plus an explicit multiplicity argument (the
   view's rows correspond 1:1 to the query's rows via a key), or restrict to
   duplicate-insensitive query contexts.

## 6. Aggregate queries

Aggregate CQ: `Q(x̄, α(y)) :- body`. Aggregate quirks prevent a single
theory (`SUM` ignores 0, `PROD` ignores 1 and is absorbed by 0, `COUNT`
ignores values, `MAX` ignores multiplicities), so results are per-function
(Cohen, Nutt, Sagiv, JACM 2007; Cohen, SIGMOD Record 2005 survey):

- `COUNT` queries: equivalent iff the bodies are bag-set equivalent — for
  irredundant bodies, iff isomorphic. The duplicate-free head
  `(x̄, y)` matters: counting corresponds exactly to bag-set multiplicity.
- `MAX`/`MIN` (and `COUNT DISTINCT`) are duplicate-insensitive: equivalence
  reduces to set-equivalence of the core queries with head `(x̄, y)`; e.g.
  `q(X, max(Y)) :- a(X,Y)` ≡ `q'(X, max(Y)) :- a(X,Y), a(X,Z)`, while the same
  pair with `count` is **not** equivalent (`a(c,0), a(c,1)` gives 2 vs 4).
- With comparisons, isomorphism stops being necessary even for `COUNT` and
  `SUM` (zeros and order constraints create non-isomorphic equivalences).
- Decomposable aggregates (`COUNT`, `SUM`, `MAX`) admit general equivalence
  characterizations even with negation (Cohen, Sagiv, Nutt, TOCL 2005).
- Containment of aggregate queries is mostly obtained by reduction to
  equivalence ("expandable" aggregates, Cohen, Nutt, Sagiv, ICDT 2003);
  queries with `HAVING` and general bag-set containment remain largely open
  in the entry.

Engine use: aggregate MV matching (rewriting a `GROUP BY` query using a
coarser or finer pre-aggregated view) should rely on (a) set containment of
the non-aggregate part, (b) a 1:1 or N:1 group mapping via FDs, and (c)
decomposability of the aggregate to roll up — never on a general aggregate
equivalence checker.

## 7. Answering queries using views

Given views `V1..Vk` and query `Q`:

- **Equivalent rewriting** (query optimization with MVs): find `R` over the
  views with `R ≡ Q`. For CQs: there is a rewriting with no more atoms than
  `Q`, so search is bounded; deciding existence is NP-complete
  (Levy, Mendelzon, Sagiv, Srivastava, PODS 1995). Under constraints:
  Chase & Backchase (Deutsch, Popa, Tannen, VLDB 1999) — chase `Q` with the
  constraints and the view-definition tgds into a *universal plan*, then
  search its subqueries that use only views; sound and complete for minimal
  rewritings whenever the chase terminates.
- **Maximally contained rewriting** (data integration, open-world sources):
  `R ⊑ Q` and maximal in a given language; algorithms: bucket, inverse
  rules (Duschka & Genesereth; may need recursive Datalog), MiniCon
  (Pottinger & Halevy, VLDB J 2001). Certain answers = answers of the
  maximally contained rewriting for CQ views and UCQ queries.

Boundary: the MV selection/maintenance machinery lives in
`materialized-views-ivm`; this file supplies the containment tests it calls.

## 8. Evaluating CQs: acyclicity and width

Data complexity of a fixed CQ is polynomial (`O(n^k)` naive), but
parameterized by query size, Boolean CQ evaluation is W[1]-complete
(Papadimitriou & Yannakakis, PODS 1997) and full RC is AW[*]-complete — so no
`f(k)·n^c` algorithm is expected for arbitrary queries. Structure restores
tractability:

**Acyclic CQs (α-acyclic hypergraph; GYO reducible).** GYO reduction:
repeatedly (a) delete a variable occurring in only one atom, (b) delete an
atom whose variables are a subset of another atom's; acyclic iff everything
reduces away. The reduction order yields a join tree.

**Yannakakis (VLDB 1981):**

```
1. Build join tree T (from GYO).
2. Bottom-up semijoin pass:  parent := parent ⋉ child      (post-order)
3. Top-down semijoin pass:   child  := child  ⋉ parent     (pre-order)
   -> every relation is now globally consistent (no dangling tuples)
4. Join along T, projecting away variables not needed above as early as possible.
Cost: O(|input| + |output|) for full CQs; Boolean acyclic CQs in O(|input|);
for projections, O(|input| · |output|) worst case.
```

Steps 2–3 form a **full reducer**; acyclic schemes are exactly those with a
full semijoin reducer, and also exactly those where pairwise consistency
implies global consistency (Beeri, Fagin, Maier, Yannakakis, JACM 1983 — see
`normalization-and-keys.md`). This is the theory behind semijoin
reduction in distributed query processing and behind bloom-filter
"sideways information passing" in hash-join pipelines.

**Bounded (generalized) hypertree width** (Gottlob, Leone, Scarcello, JCSS
2002): evaluation is polynomial for each fixed width (`n^{O(k)}`, not FPT
in `k`); acyclic = width 1. Monadic second-order
queries over bounded-treewidth *data* are fixed-parameter linear
(Courcelle), but with non-elementary `f(k)` (unavoidable unless P = NP,
Frick & Grohe 2002).

> **Beyond EDBS:** For cyclic CQs, any plan of binary joins can be
> polynomially worse than optimal: the triangle query has output bounded by
> `N^{3/2}` (AGM bound, Atserias, Grohe, Marx, FOCS 2008) while some binary
> join orders materialize `Θ(N²)` intermediates. Worst-case optimal join
> algorithms (Ngo, Porat, Ré, Rudra, PODS 2012; Leapfrog Triejoin,
> Veldhuizen, ICDT 2014) meet the bound by variable-at-a-time intersection
> over sorted/trie indexes; LogicBlox, and later Umbra-style hybrid planners,
> use them selectively for cyclic subqueries. Detect cyclicity with GYO at
> plan time to decide.

## 9. Implementation notes

- Represent a CQ as `head: Vec<Term>`, `atoms: Vec<(RelId, Vec<Term>)>`,
  `Term = Var(u32) | Const(ValueId)`, plus an equality union-find for `CQ=`.
  Freeze by mapping `Var(i)` to a reserved constant range.
- Homomorphism search: order atoms of the containing query by
  most-constrained-first (fewest candidate images, shared variables with
  already-mapped atoms), index the target atoms by `(rel, position, const)`,
  forward-check variable bindings. Cap search effort (node budget) and treat
  timeout as "not contained".
- Canonicalize before comparing: sort atoms, rename variables in first-use
  order; use canonical forms as memo keys in the optimizer (e.g. for
  CSE/MV matching), but remember canonical-form equality is isomorphism
  (bag-equivalence), strictly stronger than set-equivalence.
- Keep set-vs-bag status on every plan node so the same containment API can
  refuse set-only conclusions in bag contexts.

## 10. Tests

- Golden pairs from the literature (the `p, r, t` example; the CQAC
  `R(x,y),R(y,x)` example; the `count` vs `max` pair).
- Property: `minimize(Q) ≡ Q` (check both directions with the hom test) and
  `|minimize(minimize(Q))| = |minimize(Q)|`.
- Differential: random small instances (domain 3–4 values, 0–6 tuples per
  relation, including empty relations and self-loops) — if the checker says
  `Q1 ⊑ Q2` the evaluator must never find a counterexample; if it says
  "not contained", the frozen `D_{Q1}` is a counterexample — assert it.
- Bag mode: assert the rewriter never applies minimization when the node is
  not in a duplicate-insensitive context; random bag instances must give
  identical multisets.
